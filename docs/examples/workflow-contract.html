Why this holds together

Semantics and presentation are separate. steps is what the workflow means; views.canvas is where one UI happens to draw it. Dragging a node writes only into views, so a canvas can exist without the checklist ever knowing — and a UI we have not designed yet gets its own namespace in the same way.

needs is what makes two authoring styles possible. The canvas draws the graph; the checklist is that graph linearised. Neither is the real one. Drop needs and the canvas has nothing to connect; only then would the format really be a list.

The agent is not privileged. Its buttons above apply the same patches a user edit does. That is what “agent-editable” has to mean — one document, one set of operations, no separate agent path that can drift from what the UI writes.

A view renders what it understands and ignores the rest. “Require approval” adds one field, and three views independently find something to do with it: a pill, a marker on a node, a pause in the run. A view that had never heard of it would simply not draw it — which is the rule that lets a canvas ship later without a migration.
